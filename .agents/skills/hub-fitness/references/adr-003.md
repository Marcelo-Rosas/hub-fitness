# ADR-003 — Database-per-client

## Decisão
Cada consumidor = **projeto/DB próprio**. Isolamento = database-level. **Não** multi-tenant com `tenant_id`.

| Papel | DB | Conteúdo |
|---|---|---|
| Operador | `hub-fitness-operator` | clients, contracts, preços, tax, billing, audit, CT agregada, schema `intranet` (privado, fora da Data API) |
| Consumidor | `hub-fitness-client-<slug>` | orders…stock, products, Comex processos do importador |
| Dogfood | Client #0 Konnen | calibração — não âncora comercial |

## Consequências
- Client RLS só por papel interno (`auth.uid()` / role), sem filtro de tenant
- Operator agrega via `service_role` + FDW **somente leitura**
- Docs: `docs/adr/ADR-003-database-per-client.md`
- Provision: `supabase/client/`, `supabase/scripts/apply-client-migrations.mjs`

## Aceite
`supabase db reset` / apply client **sem** coluna `tenant_id`.
